A ConfigMap edit does not roll this DaemonSet. Drain trading workloads, then set layoutRevision, before changing sharedCpus.
Admission of a Pod does not control a later kubectl exec.

1. Wait for the plugin to be ready:

   kubectl -n {{ include "ergon-shared-cpus.namespace" . }} get pods -l app={{ include "ergon-shared-cpus.name" . }}

2. Check the resource is registered on a node:

   kubectl get node <node> -o jsonpath='{.status.allocatable.ergon\.io/shared-millicpus}'

3. Run a pod that asks for cpu and ergon.io/shared-millicpus, then check
   cpuset.cpus.effective and the ERGON_* variables inside it.

Node requirements (not set by this chart):
  - Kubernetes >= 1.33, cpuManagerPolicy: static
  - reservedSystemCPUs covers the IRQ CPU(s) and sharedCpus
  - kernel >= 6.2, cgroup v2 at /sys/fs/cgroup (the DaemonSet mounts the
    node's tree read-only into the plugin); >= 6.7 (or a backport of
    cpuset.cpus.exclusive) for the cpu-partition opt-in
  - containerd >= 2.2 with the NRI default validator on
  - node label ergon.io/shared-cpus=true
{{- if .Values.hostContract.kubeletConfig.enabled }}
  - kubelet config at {{ .Values.hostContract.kubeletConfig.path }}; the plugin
    pod does not start without it
{{- if .Values.hostContract.kubeletConfigDir.enabled }}
  - kubelet --config-dir at {{ .Values.hostContract.kubeletConfigDir.path }}
    (the kubelet must run with it); the plugin pod does not start without it
{{- end }}
  - pods labelled ergon.io/latency: hot: every exclusive CPU in isolcpus,
    no shared CPU isolated or in nohz_full, cpuCFSQuota not false, and NIC
    IRQs on reservedSystemCPUs minus sharedCpus, or the create is refused
{{- else }}
  - hostContract.kubeletConfig is off: every pod labelled
    ergon.io/latency: hot is refused at create
{{- end }}
