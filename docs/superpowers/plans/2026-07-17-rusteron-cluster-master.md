# Rusteron Cluster Client — Master Implementation Plan

> **Historical.** Written when the crate was `rusteron-cluster`; it is now crate `ergo-aeron-cluster` in `cluster/` (test harness: crate `ergo-aeron-cluster-test-support` in `cluster-test-support/`). Living doc: [2026-07-18-ergosbe-experimental-master-plan.md](2026-07-18-ergosbe-experimental-master-plan.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a handwritten-Rust Aeron Cluster *client* protocol layer on top of `rusteron-client` transport, with generated SBE codecs, a Java test harness, and comprehensive integration tests.

**Architecture:** Single `rusteron-cluster` crate (generated codecs in `src/codecs/`) depends on `rusteron-client` for pub/sub transport. Separate `rusteron-java-test-support` harness crate spawns the official Java consensus module for integration tests. Codecs generated by official sbe-tool 1.39.0 (Rust target), committed to repo, drift-checked in CI.

**Tech Stack:** Rust (rusteron-client pub/sub), Java 17+ (Gradle-built cluster jars for testing), SBE 1.39.0 (official sbe-tool, Rust target), `serial_test` (resource-safe test runs), `proptest` (property-based testing).

**Spec ref:** `docs/superpowers/specs/2026-07-17-rusteron-cluster-client-design.md`

## Global Constraints

- Aeron version: 1.52.2 (submodules at `5b62f21d91`)
- SBE version: 1.39.0 (official sbe-tool jar, `sbe.target.language=Rust`)
- No `unwrap()` — `Result<T, ClusterError>` throughout
- Never unwind through C callbacks (infallible trait callback signatures)
- Feature gate `test-harness` on `rusteron-cluster` for harness dependency
- `just` recipes for all generation/build/check/test operations
- 1.71.0 Rust edition (match workspace)
- `#[serial]` on all integration tests (shared aeron dirs, ports, SHM)
- Temporary prototype warnings in README and crate-level rustdoc

### Phase 4: Auth

- [ ] `NullCredentialsSupplier` unit tests
- [ ] `ChallengeCredentialsSupplier` — stores credentials, responds to challenge
- [ ] Integration: connect with null credentials → SessionEvent(OK)
- [ ] Integration: connect with challenge credentials → Challenge received → ChallengeResponse sent → SessionEvent(OK)
- [ ] Integration: wrong credentials → SessionEvent(AUTHENTICATION_REJECTED) → ClusterError::AuthRejected
- [ ] Integration: malformed challenge → protocol error handling

**Gate:** `cargo test -p rusteron-cluster --test integration --features test-harness auth`

### Phase 5: Egress + Messaging

- [ ] `EgressAdapter` — polls subscription, assembles fragments, dispatches to `&mut dyn EgressListener`
- [ ] `ControlledEgressAdapter` — uses `ControlledFragmentHandler`, returns `ControlledFragmentAction`
- [ ] `SessionMessageHeader` encode/decode (24 bytes: leadershipTermId + clusterSessionId + timestamp)
- [ ] `IngressSessionDecorator` — prepends header to outgoing messages
- [ ] Integration: connect → send message on ingress → receive on egress (echo service)
- [ ] Integration: multi-fragment message assembly
- [ ] Integration: controlled poll backpressure (CONTINUE/ABORT/BREAK)

**Gate:** `cargo test -p rusteron-cluster --test integration --features test-harness messaging`

### Phase 6: Failover + Leader Change

- [ ] 3-node `TestCluster::three_node_static()` fixture
- [ ] Connect to leader (member 0)
- [ ] Trigger leader step-down (admin request or kill member 0)
- [ ] Receive `NewLeaderEvent` with new leader endpoints
- [ ] Session transitions: Connected → AwaitNewLeader → AwaitNewLeaderConnection → Connected
- [ ] `on_disconnected()` → state machine triggers reconnection
- [ ] Message continuity across failover (no message loss within cluster-replicated range)
- [ ] Admin redirect during connect (connect to follower → SessionEvent(REDIRECT) → reconnect to leader)

**Gate:** `cargo test -p rusteron-cluster --test integration --features test-harness failover`

### Phase 7: Error Paths

- [ ] Malformed SBE messages → `ClusterError::ProtocolError`
- [ ] Wrong templateId on egress → error, not panic
- [ ] Truncated messages (buffer too small for header/payload)
- [ ] Connect timeout → `ClusterError::Timeout`
- [ ] Session keepalive timeout → `SessionEvent(CLOSED)` → `PendingClose` → `Closed`
- [ ] Buffer-claim too small → `ClusterError::BufferTooSmall`
- [ ] `proptest` property: any sequence of arbitrary egress fragments doesn't panic
- [ ] `proptest` property: round-trip message through generated codec types

**Gate:** `cargo test -p rusteron-cluster --lib errors; cargo test -p rusteron-cluster --lib proptest; cargo test -p rusteron-cluster --test integration --features test-harness errors`

### Phase 8: Restart + Quorum Loss

- [ ] Cluster full restart (kill all nodes, restart, rejoin) — session recovers
- [ ] Media driver restart while session active — reconnection
- [ ] 2-of-3 cluster quorum loss → session disconnected, no false leader
- [ ] Snapshot recovery after restart
- `#[ignore]` on all — run with `just slow-tests`

**Gate:** `just slow-tests` (requires Java cluster + patience)
