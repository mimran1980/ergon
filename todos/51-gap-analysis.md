## C. Audit Violations Lacking Dedicated Implementation Todos

Items the 48 audit flagged as NOT GENERATED that have no dedicated implementation todo beyond a checkbox in the umbrella 08.

### C1. `#[cold]` on error-construction paths (§10)

**48 audit:** "Not present anywhere in generated code."
**Tracking:** Referenced in 08 (list item) and 28 (cross-ref). No focused todo.

**Severity: HIGH** — HFT hot paths need `#[cold]` to keep error construction out of L1I cache. Affects the performance promise (value #3).

---

### C2. `#[expect(lint)]` over `#[allow(lint)]` (§10)

**48 audit:** Codegen uses `#![allow(...)]` and `#[allow(unused_unsafe)]` — stale suppressions go undetected.
**Tracking:** Only in 08.

**Severity: MEDIUM** — code quality, not wire-critical.

---

### C3. `const` assertions in generated code (§10)

**48 audit:** Nothing like `const _: () = assert!(size_of::<MessageHeader>() == 8)` is emitted.
**Tracking:** Only in 08.

**Severity: HIGH** — const assertions catch generator bugs at compile time. Without them, a generator regression that changes `MessageHeader` size goes undetected until runtime.

---

### C4. Per-field `FieldMeta` const module (§5)

**48 audit:** NOT GENERATED. Required by design: one `FieldMeta` const per field with `id`, `since_version`, `offset`, `presence`, `null_value`, `semantic_type`.
**Tracking:** Only in 08.

**Severity: HIGH** — `FieldMeta` is foundational for generic code, `MessageVisitor`, `debug_wire`, and tooling. Without it, all §5 metadata features have no data source.

---

### C5. `SEMANTIC_VERSION` / `SEMANTIC_TYPE` associated consts (§5)

**Tracking:** Only in 08.
