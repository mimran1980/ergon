# ErgoSBE Performance Optimisation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep ErgoSBE wire-compatible with official SBE while making every measured hot path comparable to or faster than Aeron SBE, then find further measured speedups.

**Architecture:** Optimise the generated Rust artefact, not abstract codegen theory. Every optimisation starts from Criterion numbers and generated-code/assembly inspection, changes the smallest codegen surface in `sbe/src/codegen.rs`, regenerates `sbe/tests/golden/car_example.rs`, and is kept only if benchmarks improve or preserve parity within confidence intervals.

**Tech Stack:** Rust 1.95 workspace, `ergosbe`, `ergosbe-benchmarks`, Criterion, generated Rust via `syn`/`quote`/`prettyplease`, Aeron SBE reference benchmark code.

## Global Constraints

- Wire compatibility is a non-negotiable floor. Reject any speedup that changes generated bytes or official-SBE decoder behaviour.
- Performance comes first among valid designs. Hot paths must stay allocation-free and never slower than Aeron without an explicit opt-in.
- Rust ergonomics and safety are welcome only when zero-cost or off the hot path.
- Simplicity wins when performance and safety are equal.
- Do not add `push_str(&format!(...))` to `sbe/src/codegen.rs`; every codegen change must shrink or at least not grow string-template debt.
- Do not use bytemuck, Pod, zerocopy transmute, SIMD bulk copy, nightly APIs, specialization, or broad per-field `_unchecked` APIs.
- Preserve the existing dirty worktree. Read `CLAUDE.md`, `sbe/design/DECISIONS.md`, and `phase2-completion-goal.md` before edits.

## Task 5: Investigate Fixed-Tail Entry Advance Precomputation

**Files:**

- Modify: `sbe/src/codegen.rs`
- Optionally modify: `ergosbe-benchmarks/benches/perf_parity_bench.rs`
- Regenerate: `sbe/tests/golden/car_example.rs`
- Sync: `sbe/benches/generated/car_patched.rs`

**Interfaces:**

- Consumes: generated group entry iterators and `tail_offset_N` helpers.
- Produces: faster `next()` for fixed-tail group entries only; variable var-data
  entries must keep dynamic tail scanning.

- [ ] **Step 1: Identify generated tail chains**

Run:

```sh
rg -n "tail_offset_[0-9]|impl Iterator|fn next" sbe/tests/golden/car_example.rs
```

Classify each group entry:

- Tail-free fixed entry: already eligible for direct `acting_block_length` advance.
- Fixed-tail entry: nested groups/fields with statically computable total advance.
- Variable-tail entry: contains var-data or variable-count nested data; not
  eligible for precomputed per-entry advance.

- [ ] **Step 2: Add or run a targeted iterator benchmark**

If no benchmark isolates tailed group `next()`, add one to
`ergosbe-benchmarks/benches/perf_parity_bench.rs` that repeatedly iterates the
smallest generated tailed group and black-boxes a scalar from each entry.

- [ ] **Step 3: State the hypothesis**

Only proceed if measurement shows a real gap:

`Group iterator next is slow because each entry recomputes tail_offset_N back to
tail_offset_0, causing O(depth) bounds checks per entry even when the entry's
tail advance is fixed for this schema and acting version.`

- [ ] **Step 4: Implement only the fixed-tail case**

Generate a cached per-instance `entry_advance` or equivalent direct stride only
for entries whose full encoded length is statically computable for the acting
version. Do not precompute entries with var-data or runtime-count nested tails.

- [ ] **Step 5: Verify and compare**

Run the full verification ladder. Reject the change if any versioning, wire, or
allocation test fails.

- [ ] **Step 6: Commit**

```sh
git add sbe/src/codegen.rs sbe/tests/golden/car_example.rs sbe/benches/generated/car_patched.rs ergosbe-benchmarks/benches/perf_parity_bench.rs ergosbe-performance-optimisation-goal.md
git commit -m "perf: precompute fixed-tail group entry advance"
```
