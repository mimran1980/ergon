# SBE parity benchmarks

Head-to-head benchmarks comparing ergon against sbe-tool (official
simple-binary-encoding Rust codegen). Generated by Gradle from the same
schema files.

## Fairness rules (non-negotiable)

Every parity benchmark must compare **identical logical work**. These
rules are the checklist — verify them before adding or reviewing any
benchmark.

### 1. Header handling

| ergon | sbe-tool | Fair? |
|-------|----------|-------|
| `wrap_and_apply_header(buf, 0)` | `wrap(buf, 8)` + `header(0)` | ✅ Both write header + body |
| `wrap(buf, 8)` | `wrap(buf, 8)` (no header) | n/a — sbe-tool API requires `header()` to reach body |

**sbe-tool convention:** `wrap(buf, ENCODED_LENGTH)` positions the encoder
at the body start (offset 8). `header(0)` writes the message header at
absolute position 0 via a separate encoder. Body fields use `self.offset`
(which is 8) as their base.

**ergon convention:** `wrap_and_apply_header(buf, 0)` writes the header at
0 then positions the body at 8. `wrap(buf, 8)` is body-only — only use
when comparing against a body-only sbe-tool path (which doesn't exist for
message-level encoders).

**Rule:** ergon arm must use `wrap_and_apply_header` (NOT `wrap`) when
comparing against sbe-tool message encode.

### 2. NEVER use `try_xxx` in benchmarks

| Forbidden | Use instead | Why |
|-----------|------------|-----|
| `try_wrap_and_apply_header(...).unwrap()` | `wrap_and_apply_header(...)` | `try_` validates header fields — sbe-tool doesn't validate |
| `try_from(...).unwrap()` | `wrap(...)` with pre-computed header | `try_from` reads + validates header — sbe-tool `wrap` doesn't |

sbe-tool's `wrap()` + `header()` does NOT validate template_id, schema_id,
or version. ergon's `try_wrap_and_apply_header` / `try_from` DO validate.
If ergon validates but sbe-tool doesn't, ergon does extra work and the
comparison is invalid.

`try_compute_encoded_length_with_header` is acceptable OUTSIDE the timed
path for buffer sizing — it's not compared against sbe-tool, just used
to allocate ergon's buffer.

### 3. Encode layout parity

Both arms must produce byte-identical wire output. Verify:
- Encoded length matches between ergon and sbe-tool
- Actual bytes match (for at least one sample message)

Add a `assert_eq!(ergo_len, tool_body_len + 8)` assertion **before** the
timing loop (not inside it).

### 4. Field access count

Both arms access the same fields the same number of times. If one arm
reads 2 fields and the other reads 3, the comparison is invalid.

### 5. Buffer operations

One pre-sized buffer reused across iterations. No `ReadBuf::new` /
`WriteBuf::new` divergence that gives one arm free work.

### 6. Group/var-data traversal

When comparing full-message decode, both arms traverse every group entry
and every var-data field. sbe-tool's `advance()` forces consumption —
ergon must consume the same data.

### 7. Pre-computation

If one arm pre-computes header fields (`block_length`, `version`) outside
the timed loop, the other must do the same.

## Running

```sh
# Full parity bench (all scenarios)
cargo bench --bench perf_parity_bench

# Group encode comparison
cargo bench --bench group_encode_bench
```

## Red flags

If any of these appear, STOP and fix before benchmarking:

- `try_wrap_and_apply_header` in a timed path
- `wrap(buf, 8)` (body-only) in ergon vs `wrap(buf, 8)` + `header(0)` in sbe-tool
- Different field subsets in two arms of the same scenario
- ergon/sbe-tool ratio exceeds 1.00 without documented reason
- Length assertion missing from a parity benchmark
