## Problem & Gaps

In low-latency and HFT systems, writing raw flyweight encoder/decoder boilerplate directly inside business logic causes several issues:
1. **Flyweight Misuse:** Developers must manually manage the lifecycles of flyweight structs and their underlying buffers, leading to bugs when flyweights are accessed out of scope (lifetime violation of network ring buffer data).
2. **Incorrect SBE Field Ordering:** Developers must manually write fields, groups, and var-data in the exact order declared in the XML schema. A single out-of-order write/read corrupts the message offsets.
3. **Complex Dispatching Boilerplate:** Developers must write custom `match template_id` dispatch loops, unpack headers, and coordinate frame validation for every message type.

The Aeron Premium **SBE Domain Mapper** solves this by generating **Adapters** (which multiplex and decode incoming streams into high-level event handlers) and **Proxies** (which expose high-level method calls to write messages, ensuring correct SBE write ordering and hiding flyweight complexity). We should implement a similar generator module in ErgoSBE.

## What needs to be done

1. **Adapter Generation (Event Dispatcher):**
   - For every schema, generate a dispatch trait `SchemaEventAdapter<'a>` containing callback hooks for each message:
     ```rust
     pub trait SchemaEventAdapter<'a> {
         fn on_car(&mut self, header: &MessageHeader, car: &CarDecoder<'a>) -> Result<(), DecodeError> { Ok(()) }
         fn on_price_update(&mut self, header: &MessageHeader, price: &PriceUpdateDecoder<'a>) -> Result<(), DecodeError> { Ok(()) }
     }
     ```
   - Generate a single dispatcher function `dispatch_message<'a>(buf: &'a [u8], offset: usize, handler: &mut impl SchemaEventAdapter<'a>) -> Result<usize, DecodeError>` that automatically parses the header, verifies `schemaId`, and dispatches to the correct handler callback.
   - Prefer a scoped/HRTB adapter variant (`for<'a>`) so decoded flyweight views
     cannot escape the callback lifetime or be stored in long-lived handler
     state by accident.
   - For messages with ordered tails, offer an adapter mode that receives a
     type-state tail cursor or consumes it internally so handler code cannot
     accidentally read groups/var-data out of schema order.

2. **Proxy Generation (Event Encoder):**
   - Generate a `SchemaProxy<W: SbeWriter>` struct that encapsulates message writing:
     ```rust
     pub struct SchemaProxy<W> {
         writer: W,
     }
     ```
   - Generate proxy methods for each SBE message that take all required fields, groups, and var-data payloads as parameters or via ordered builders, ensuring fields are written in the exact SBE schema order:
     ```rust
     impl<W: SbeWriter> SchemaProxy<W> {
         pub fn send_car(&mut self, serial_number: u64, model_year: u16, available: BooleanType, ...) -> Result<usize, EncodeError>;
     }
     ```
   - Provide integration abstractions for zero-copy memory buffers (e.g. mapping directly into Aeron `tryClaim` buffers).
