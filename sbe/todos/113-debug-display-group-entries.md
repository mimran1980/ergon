# Debug/Display: iterate and print group entries instead of just count

**Blocked by:** 111 (Result-bearing Iterator — groups with tails return `Result<EntryDecoder>`)
**Ref:** user request

## Problem

`generate_decoder_display()` in `sbe/src/codegen.rs` line ~3019 prints only the
entry count for repeating groups:

```rust
for g in &msg.groups {
    write!(f, "{sep}{snake}: {} entries", g.len())?;
}
```

Example output: `fuel_figures: 3 entries` — useless for debugging. The user
wants to see the actual field values of each entry.

## Design

Iterate through group entries and print each one with its fields:

```rust
for g in &msg.groups {
    write!(f, "{sep}{snake}: [")?;
    if let Ok(decoder) = self.{g_snake}() {
        for (i, entry) in decoder.enumerate() {
            if i > 0 { write!(f, ", ")?; }
            // Handle Result wrapper from todo 111
            match entry {
                Ok(e) => write!(f, "{{ ... }}")?,  // entry fields
                Err(_) => write!(f, "{{ err }}")?,
            }
        }
    }
    write!(f, "]")?;
}
```

Each entry should print its own fields. The entry decoder already has field
accessors — iterate over the entry's fields and print name: value pairs.

### Nested groups within entries

Groups within group entries (e.g., `acceleration` within `performanceFigures`)
also need their own Display impl. Those are generated by `generate_group_decoder`
and should get the same treatment.

### Complexity

The entry field iteration is the same as the message-level field iteration
but applied to each entry. For entries with nested groups, recursively
iterate.

### Ponytail option

Simplest: iterate entries, print each entry's scalar fields only (skip nested
groups and var-data within entries for now). The scalar fields are the most
important for debugging.

```rust
// For each entry in the group:
write!(f, "{{ speed: {}, mpg: {} }}", entry.speed(), entry.mpg())?;
```

But entry field names vary per schema — need to generate field-by-field like
the message Display does.
