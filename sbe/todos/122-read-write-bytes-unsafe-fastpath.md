# Replace read_bytes/write_bytes const helpers with Aeron-style slice reads

**Ref:** user request. The current `read_bytes::<N>`/`write_bytes::<N>` helpers
use `while i < N` loops internally. Aeron does NOT — it uses direct slice
indexing: `slice[index..index+N].try_into().expect("...")`.

**Status: DONE**

## Verification note (2026-07-08)

This todo captured the read/write helper change and the const-callsite conflict
it exposed. The design decision is now explicit: `read_bytes`/`write_bytes` are
runtime hot-path helpers, and generated methods that call them should not be
`const fn`.

Historical observed failures:
- `RUSTC_WRAPPER="" cargo test -p ergosbe --features bound-check-disabled -- --test-threads=1`
  failed with generated `E0015` errors.
- `samples/exchange-orderbook` previously failed with the same generated
  `E0015` class; the current sample compile gate passes, so this is a
  regression guard rather than the current sample state.

If similar failures recur, remove constness from the generated buffer-reading
callsite. Do not make the byte helpers slower to satisfy const evaluation.

## Current state

```rust
// Generated by gen_schema:
pub const fn read_bytes<const N: usize>(buf: &[u8], offset: usize) -> [u8; N] {
    let mut bytes = [0u8; N];
    let mut i = 0;
    while i < N {
        bytes[i] = buf[offset + i];
        i += 1;
    }
    bytes
}
```

Call sites: 21 `read_bytes` + 17 `write_bytes` = 38 calls across generated code.
The loop is centralized (one loop body in helpers, not duplicated), but:

1. **Safe path**: `while i < N` loop — compiler unrolls for small N, but
   `slice[index..index+N].try_into().unwrap()` is simpler and potentially
   faster (single memcpy for large N). Trade-off: not const fn.
2. **bound-check-disabled**: should use `unsafe { ptr::read_unaligned(...) }`
   for zero-overhead reads, like Aeron's unchecked path.

## Design — Aeron comparison

Aeron's `ReadBuf::get_bytes_at`:
```rust
pub fn get_bytes_at<const N: usize>(slice: &[u8], index: usize) -> [u8; N] {
    slice[index..index+N].try_into().expect("slice with incorrect length")
}
```

No loop. Single slice operation. Compiler emits optimal code for any N.

## Design — ErgoSBE dual-path

```rust
/// Read N bytes from buf at offset.
#[inline(always)]
pub fn read_bytes<const N: usize>(buf: &[u8], offset: usize) -> [u8; N] {
    #[cfg(not(feature = "bound-check-disabled"))]
    {
        buf[offset..][..N].try_into().expect("read_bytes: buffer too short")
    }
    #[cfg(feature = "bound-check-disabled")]
    unsafe {
        core::ptr::read_unaligned(buf.as_ptr().add(offset) as *const [u8; N])
    }
}

/// Write N bytes into buf at offset.
#[inline(always)]
pub fn write_bytes<const N: usize>(buf: &mut [u8], offset: usize, bytes: &[u8; N]) {
    #[cfg(not(feature = "bound-check-disabled"))]
    {
        buf[offset..][..N].copy_from_slice(bytes);
    }
    #[cfg(feature = "bound-check-disabled")]
    unsafe {
        core::ptr::write_unaligned(buf.as_mut_ptr().add(offset) as *mut [u8; N], *bytes);
    }
}
```

- Safe path: slice indexing with bounds check
- `bound-check-disabled`: unsafe pointer read/write — zero bounds check, single load/store

## Endianness

`ptr::read_unaligned` reads native-endian. For LE schemas on LE machines, this
is zero-cost. For BE schemas on LE machines, the raw bytes must be run through
`from_be_bytes()`. The `read_bytes` helper returns raw `[u8; N]` — the CALLER
applies `from_le_bytes`/`from_be_bytes` based on schema byte order. So the
helper itself doesn't need endian awareness.

## Trade-off

- `try_into().expect()` is NOT const fn → accessors drop `const fn`
- Aeron doesn't use const fn for accessors either — `#[inline]` instead
- Performance > const fn for a low-latency codec
- Type-state does not change this: it proves API order, not that a runtime
  buffer read/write can or should be const-evaluated
- `bound-check-disabled` unsafe path: `ptr::read_unaligned` reads raw bytes,
  caller applies `from_{le,be}_bytes` — correct for both endiannesses

## Const-callsite policy

Remove `const fn` from every generated method that calls runtime byte helpers.
Keep `const fn` only for pure/no-buffer helpers: enum/set `raw()` and
`from_raw()`, constant-value fields, metadata/layout constants, static templates,
pure length helpers, and semantic newtype wrappers.

Do not add a separate const-compatible buffer-read API unless a real user
workflow needs it and benchmarks prove it does not leak slower code into the
runtime path.
