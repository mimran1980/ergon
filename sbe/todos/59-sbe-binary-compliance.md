# SBE binary compliance verification

**Blocked by:** all wire-parity todos (01, 02, 03)

Once all implementation is complete, run a comprehensive binary compliance
verification against the official SBE reference implementation. This is the
final gate before v1.

## Strategy

1. **Harvest every test fixture** from `simple-binary-encoding/` submodule
   (Java-generated `.sbe` binary files, Rust reference tests, schema XMLs).
2. **For each fixture:** parse schema → generate ErgoSBE code → compile →
   decode fixture → assert every field → re-encode → assert byte-exact match
   with fixture.
3. **Cross-tool round-trip:** encode with ErgoSBE, decode with upstream Java
   reference, compare. Or encode with ErgoSBE, decode with upstream Rust
   reference, compare.
4. **Self round-trip:** ErgoSBE encode → ErgoSBE decode → semantic equal.
5. **Golden file diff:** generated code for every upstream schema matches
   expected output (regen-stability test already catches regressions on
   `car_example`).

## Acceptance criteria

- [x] All upstream `.sbe` binary fixtures decode correctly (field-by-field)
- [x] Re-encoded output matches upstream fixture byte-for-byte
- [x] All upstream XML schemas parse without error
- [x] All upstream XML schemas generate compilable Rust code
- [x] Round-trip (encode→decode→semantic-equal) for every message type in
  every upstream schema
- [x] `cargo test --workspace` includes all compliance tests
- [x] Report: which schemas/fixtures pass, which fail, why
- [x] Differential Testing: Implement an automated differential testing harness that randomly generates valid message payloads, encodes them using the upstream Java SBE tool, encodes them using ErgoSBE, and asserts the generated byte buffers are identical.
