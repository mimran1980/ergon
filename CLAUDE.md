# ErgoSBE — repo guide for Claude Code

ErgoSBE: opinionated, idiomatic Rust code generation for Simple Binary Encoding
(SBE). Wire-compatible with official SBE; API-shaped for Rust. Target: low-latency
trading. **Full design record: [`design/DECISIONS.md`](design/DECISIONS.md).**

When a task touches generated-code shape, version handling, or wire layout, read
`design/DECISIONS.md` first — this file holds only the load-bearing invariants and
traps that matter on every task.

## Core invariants (do not violate without updating DECISIONS.md)

- **Wire compat is priority 1.** Generated bytes must equal official SBE for the same
  logical message. The headline test is byte-exact parity with the upstream
  `.sbe` fixtures.
- **Decoders are always version-aware.** Tail offset = `body_offset +
  header.block_length()` (the *wire* blockLength, never the compiled one). Required
  v0 fields return `T`; optional fields and `sinceVersion > 0` fields return
  `Option<T>`.
- **Optional null is not version absence.** Public accessors collapse both to
  `None`; generated `raw_foo()` accessors preserve wire sentinels for HFT hot loops.
- **No transmute from the buffer.** Read field-by-field with `from_{le,be}_bytes`
  (unaligned-safe, endian-correct). `repr(C)` is nominal only.
- **Generated code lives in the user's crate** (build.rs module, not a separate
  crate) so the orphan rule lets users impl serde/rust_decimal/inherent methods.
- **SBE is not a transport frame.** Unknown-template forwarding requires an external
  frame length; use `FrameCursor` / `AnyMessage::decode_frame` for feed buffers.
- **Resolve schema layout, do not hard-code it.** `headerType`, `dimensionType`,
  `byteOrder`, defaults/nulls/min/max, block lengths, field ids, and schema hash are
  resolved in IR validation before codegen.
- **Safe by default.** All `unsafe` is opt-in: the `bound-check-disabled` feature, or
  per-call `…_unchecked` methods. Generated crates that expose unchecked APIs must
  not inherit a blanket `unsafe_code = "forbid"` lint.
- **Error taxonomy.** `DecodeError` and `EncodeError` are hand-rolled with
  `core::error::Error`; variants carry context for recovery (no heap allocation).
  See DECISIONS.md §8b.
- **Sealed `SbeMessage` trait** with `#[diagnostic::on_unimplemented]`; decoded
  dispatch is the separate `AnyMessage<'a>` enum.

## Tricky areas (the traps that bite)

1. Tail offset from **wire** blockLength, not compiled — classic SBE bug.
2. Rust enums can't hold unknown discriminants → enums use the newtype (`E3`).
3. `repr(C)` transmute is a trap (unaligned + native-endian + `packed` UB).
4. Orphan rule → generated types must be in the user's crate.
5. `Iterator::next` returns `Option` → group accessor returns `Result` (validates
   extent), iteration is infallible within.
6. Encoder is the γ hybrid: scalars `&mut self`, tail by-value type-state; no
   enclosing `encode(|c| …)` closure.
7. `as_str_unchecked` is `unsafe fn` (zero-cost), distinct from `bound-check-disabled`.
8. No silent compiled-`blockLength` decoder path — always version-aware.
9. SBE's header is not total length; unknown-template forwarding needs external framing.
10. Optional null and version absence need both ergonomic accessors and raw accessors.
11. `const fn` on primitive field accessors + `slice::as_chunks` for fixed arrays/groups.
12. `#[cold]` on error paths, `#[expect]` over `#[allow]`, const assertions in
    generated code.

## Codegen: MUST use `syn`/`quote!`, NEVER `push_str(&format!(...))`

- **All generated Rust source must be built with `quote::quote!`**, not string
  concatenation. `syn` provides the AST types; `quote!` gives compile-time syntax
  checking.
- **Formatting is `prettyplease::unparse` only.** No external `rustfmt` subprocess,
  no `Command::new("rustfmt")`. Every `generate()` path ends with
  `prettyplease::unparse(&file)`. The `.unwrap_or(src)` fallback is a bug — it
  silently swallows parse errors and returns unformatted code. Fix it to `expect`
  or propagate the error.
- **No new `push_str(&format!(...))` in codegen.rs.** When modifying existing
  string-based templates, convert the affected section to `quote!` rather than
  adding more string pushers. This is non-negotiable — the user explicitly
  rejected format!-based codegen.
- **Migration tracked as todo 17.** The existing ~3000 lines of string-based
  templates are technical debt. Each change to codegen.rs should shrink that
  debt, not grow it.

## Workflow

- **Done means verified.** A checkbox is only `[x]` if there is a running test
  that proves it. "Looks correct" is not done. "Generated code compiles" is not
  done. A unit test that asserts the specific behaviour is done. When marking a
  todo complete, the test proving it must already exist and pass.
- **Tests are the source of truth.** Iterate against the golden/interop tests until
  green; do not reason about wire correctness in the abstract. Compare structures for
  semantic equality; compare bytes for wire parity. The upstream
  `simple-binary-encoding/` submodule holds the official `.sbe` fixtures and the
  reference schemas.
- **Ad-hoc debugging:** write throwaway input to a project-local `tmp/` (gitignored)
  or a temp example, pass by path, remove after. Do not pipe via `echo | cmd`.
- **Error tests:** snapshot the fully-rendered diagnostic, not `format!("{err}").contains(...)`.
- Prefer LSP (`workspaceSymbol`/`goToDefinition`/`findReferences`) over grep for Rust
  navigation; grep only for literal strings in non-Rust/generated files.
- Match surrounding style; smallest correct change; imperative-mood changelog entries
  that earn their place.

cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
